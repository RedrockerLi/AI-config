# 场景推演

这些假设场景展示如何运用[协作原则](principles.md)推理具体问题。它们不是可供选择的协作模式；任务中的证据、依赖和授权不同，安排也会不同。

## 迁移中先到的事实如何解除依赖

一项日志迁移覆盖在线请求、支付处理和后台任务。用户要求保留请求关联、敏感信息保护和原有错误等级。各领域能独立调查现状，实现则共同依赖“关联如何跨边界传播”和“敏感信息保护覆盖什么”这两个含义。

发起者交出支付兼容性与后台调用路径的调查后，继续实现自己负责的在线入口和端到端检查骨架。后台调查先确认队列会保留关联字段，但重试路径仍在检查中。这条已确认的事实带有真实消息样本和适用版本，可以立即支持正常路径的连接；重试行为仍保留为未决，不必等整份调查结束才使用已有证据。

支付调查随后发现嵌套对象中也会出现敏感信息。若公共承诺本来就要求全部去除，则支付适配器可以局部修复；若约定只覆盖顶层字段，这个发现会改变多个实现的前提，需要修订共同定义。受影响者明确哪些代码和测试必须调整，未依赖这个假设的工作继续推进。

此前基于顶层字段写出的候选补丁稍后到达。接收者按其旧基线判断可用部分，而不因它最后提交就覆盖新语义。一条真实请求到后台的切片可以提前验证连接，完整迁移仍要覆盖必要领域、重试和保护规则。

这里的加速来自事实一旦足以支持行动就被使用，以及发起者在等待期间完成了独立工作。它依赖实际能交付中间结果的工具；若环境只能返回最终结果，可以把有独立用途的调查边界设得更合适，无须虚构异步能力。

## 两个参与者直接解决边界问题

导出任务已有明确承诺：结果按原顺序流式写出，消费者可以中止，内存受总预算约束。一个 agent 负责读取记录，另一个负责压缩输出。压缩者发现当前读取器会预先保存整批记录，给出了测量和一个逐条消费的示例。

双方核对后发现，对外顺序和错误含义都可以保持。读取者自主改用惰性迭代，压缩者调整消费与关闭逻辑；两人约定共享接口的修改归属，并用取消和失败输入检查边界。事实和产物直接传递，整体负责人只需要取得已核验的结果及资源变化，逐项转发这些细节没有额外价值。

如果优化要求重新排序记录，影响就超出两人的局部实现权。他们保留测量和候选方案，把取舍交给覆盖用户承诺的责任方；能否变更承诺按已有授权决定。先找可局部撤回的做法，并不意味着可以悄悄改变外部行为。

双方各自的内存测试也不足以验收总预算。若读取器和压缩器都把缓冲转移给调用方，局部数字很好看，整体仍可能更差。真正被接收的是组合后的行为和消耗。

## 调查改变了任务边界

一个服务的偶发失败最初被怀疑与网络或缓存有关。两条调查分别检查连接记录和缓存状态，发起者同时构造能够记录调用顺序的复现。分工围绕证据空缺展开，并没有要求每人提交一份修复。

网络调查较早证明，在本地连接上也能触发故障。这个结果削弱了网络解释，却还不足以排除全部外部因素。复现进一步显示，两个调用者把同一个可变对象交给了不同请求。先前看似分开的网络和缓存模块，其实都受对象生命周期支配。

现在值得保持完整的是这段生命周期推理。最接近相关证据的参与者接手共同状态的修复，另一位用独立调度构造反例；已有日志成为两者的共同依据。原先计划开展的网络参数调优已不影响决策，可以结束。网络路径的必要回归依然保留，结束一条解释路线不会免除对用户承诺的验证。

隔离缓存后故障消失，也可能只是改变了执行时序。只有能区分这些解释的观察才适合支持根因结论。若实验共用环境，还要协调重置和运行窗口，让一次实验不暗中改变另一次的条件。

这种重组没有要求所有工作重新开始。可靠事实被保留，失效的任务划分被替换；参与者的责任跟随问题结构变化。

## 临近交付时增加能力是否值得

功能实现大体齐全，但完整场景尚未通过。若阻塞来自两个组件对重试的不同解释，更多人同时改代码可能增加协调成本。让熟悉两端的人澄清含义，其他人提供复现与证据，可能比再开几条修复分支更快。

若剩余工作是几个互不干扰的平台兼容检查，版本明确、环境独立、结果能被及时接收，那么新增参与者仍可能缩短历时。检查中发现公共问题时，只暂停真正依赖它的工作。若各路结果已经在等待核验，新增能力更适合帮助接收而非继续产出候选实现。

延期本身不能决定并发规模。估计应包括剩余交接、整合和返工；省略原定必要检查只是改变了承诺。反过来，若剩下的只是一个清楚、可逆的局部修正，直接完成并作相称验证即可，早期的协作规模无需保留。

## 设计探索中的用户假设与自主权

一个查询工具需要兼顾响应速度、结果新鲜度和维护成本。不同参与者可以探索不同算法，也可以并行测量查询与更新频率。但如果一方假设用户是偶尔查询的分析师，另一方假设用户是持续监控的值班人员，比较缓存实现就缺少共同基础。

把画像和频率判断的依据明确下来。如果两个合理的频率估计会导向不同方案，这个未知值得测量或取得用户判断；若它只影响内部可逆的参数，可以先在明示假设下试验。其他 agent 重述同一个估计不会增加证据。

界面原型能检验用户是否理解新鲜度提示，性能实验能约束主要成本。展示一次缓存结果还不能证明失效、并发更新和异常恢复正确。稳定的共同语义一旦有了依据，参与者可以自主改变内部表示，或让普通入口和快捷操作采用不同呈现方式。

候选方案无需全部做成产品。某条路线失去价值后，保留它提供的测量和反例；吸收其局部优点时重新检查组合前提。新版本也不需要保留每个 agent 提议的选项：选项的理解、组合和维护成本同样由用户承担。

## 局部全绿，组合后依然失败

加载器与汇总组件分别通过测试，集成后却重复读取。加载器将空游标解释为“结束”，汇总组件将它解释为“从头开始”。相同数据结构、互不冲突的文件修改，都没有保证相同含义。

双方根据完整用户场景核对语义，在权威定义与实现中保持一致，再用边界输入验证组合。审查者从原始承诺寻找反例，而不只是确认两份报告互相赞同。临时跳过逻辑若只是帮助继续诊断，应带着其覆盖范围和后续责任；它不能替代正式修复。

即使审查报告已经指出空游标问题，执行者回复“已理解”，也要确认实际代码、调用者和检查随之改变。复制文档中的预期输出不会产生运行证据，旧版本的通过记录也不能验收当前版本。共享基线失效时先恢复受影响部分，其他独立工作可以继续。

## 接续时处理迟到结果和在途操作

一项迁移的总结写着“适配器完成，测试通过”，接手者却发现当前集成失败。那些检查基于旧接口，还有一个后台生成任务没有结束。继续执行旧任务可能重新写入已经更新的产物。

接续材料应让新参与者恢复当前契约、修改基线、实际产物、检查范围和未决依赖，仍在运行的操作也属于工作状态。接手者核对其影响，视需要让旧操作结束、隔离输出或取得终止确认；不能把发出停止请求当作已经停止的证据。

某份迟到报告包含有用的兼容事实，但建议依赖旧接口。保留事实的来源和条件，重新判断建议，避免整份丢弃或整份照用。若几份子报告都转述同一个未经核实的兼容假设，它们仍只构成一个待核实判断。

有效交接不需要重放全部历史，但应提供能改变下一步行动的证据入口。接手者据此完成必要验证、关闭真实缺口，再决定是否需要新的分工。
