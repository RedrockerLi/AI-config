# 多 agent 协作的心智模型

把协作看作对认知、决策、依赖和交付责任的组织。加速的对象是用户得到一个完整、可信结果的过程。独立上下文可以扩大调查深度与视角，行动重叠可以缩短等待；这些收益都要经过接收、组合与验证才能兑现。

协作结构由问题生长出来。可以分解、重组、并行探索、集中推理，也可以让同一个 agent 连续完成工作。只要能解释它如何减少关键等待、发现重要事实或降低返工，就可以创造适合当前任务的安排。角色、人数和阶段都只是可调整的设计变量。

## 沿依赖创造可用进展

形成足以支持当前决策的共同模型：谁使用结果、需要什么行为、哪些约束必须满足、什么证据能证明完成。把事实、暂用假设与未决问题区分开，使参与者知道哪些内容可以依赖。

顺着依赖寻找真正的瓶颈。任务可能缺少实现能力，也可能等待共享语义、真实环境、验证资源或一次整体取舍。分工应交出能解除依赖的结果。需要反复交换中间推理的部分适合保持连续；能在稳定边界内独立调查、实现或核验的部分适合展开。相互独立的工具调用未必需要各自增加一个 agent。

委派后，发起者继续推进不依赖返回结果的关键工作。足以解除某条依赖的事实一旦可用，就传给实际使用者，保留其条件和未决部分；完整接收与整体验收仍需覆盖全部必要工作。安排可以随证据重组，也可以结束已经失去用途的探索。

当并行没有缩短交付、产物积压或新增 agent 的价值不清楚时，深入[依赖与有效并行](references/principles.md#依赖与有效并行)，判断认知收益、关键路径和接收容量。

## 用概念完整性支撑局部自主

各部分需要呈现一致的用户模型：相同术语有相同含义，相似操作遵循可预测的规则，局部取舍服务于同一个目标。契约规定其他部分可以依赖什么，并为内部方法保留自由。委派目标、必要背景、约束和完成依据，让最接近证据的 agent 作出局部判断。

原则冲突时，追踪决定会影响谁、错误能否低成本撤回，以及缺少的事实会不会改变行动。影响局部且可逆的选择可以先试；会让多路工作大幅返工的共同假设值得先澄清。实现证据可以推翻契约，变更责任随影响范围扩大，稳定性并不要求维护已经被否定的决定。

参与者可以在责任范围内直接协调边界，跨越其授权的取舍需要相应范围的裁决。整体责任覆盖冲突、缺口和用户承诺；分层责任可以减少集中转发与审批。

当任务切分反复联动、局部自主与统一设计冲突时，深入[契约与决策边界](references/principles.md#契约与决策边界)。

## 把知识当作有条件的状态

共享目标、契约、版本和关键证据，局部细节按依赖读取。上下文是可能过时的副本，摘要是有损压缩。结论应带着适用条件和可追溯依据传递；原始产物能直接引用时，减少逐层转述。

共同假设变化后，找到受影响的工作与证据，通知依赖者并重新判定有效性。消息到达不代表理解已经同步，晚到结果也不能自动覆盖更新的决定。交接包含产物、验证范围、未决依赖和仍在运行的操作。

当上下文过大、结论冲突或需要接续工作时，深入[知识与工作状态](references/principles.md#知识与工作状态)，决定哪些信息必须共享、哪些可以按需恢复。

## 让整体尽早接受现实检验

用能够运行、可以解释其覆盖范围的增量持续检验设计。原型帮助回答未知，局部检查验证组件承诺，交互与用户场景检验整体结果。每种证据都有版本、环境和适用条件。

依据失败所在的层次调整工作：局部缺陷可以局部修复，共同语义冲突需要共享裁决，需求误解需要回到用户目标。独立意见有助于发现盲点，分歧仍需用证据处理；相同前提下的多数赞同不构成独立验证。

综合随着可用证据到达持续进行，判断相互关系、冲突和缺口。完成依据是承诺范围内的整体行为及必要证据；剩余分支只有在确认不再承担必要工作后才可结束。资源边界可以要求停止投入，不能把停止改称完成。

当局部检查通过却仍缺整体把握，或需要评价协作是否有效时，深入[反馈与整体交付](references/principles.md#反馈与整体交付)。这些原则共同约束工作，不构成固定执行阶段。
